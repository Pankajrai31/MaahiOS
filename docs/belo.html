Rendered Page Area (Viewport)

In a learning browser, this area is produced by: (1) networking fetch, (2) HTML parse, (3) layout, (4) paint, (5) input events.

Start simple: text-only rendering and basic links. Then add images, then a small CSS subset, then (optionally) JS.

HTML Parser
Builds a DOM-like tree from HTML tokens.
Layout
Turns DOM into boxes/lines (flow layout).
Painter
Draws text/rectangles/images to the screen.

UI EVENT FLOW (high level) User types URL + Enter -> UI Controller builds NavigationRequest -> Networking fetches document -> Parser creates DOM tree -> Layout computes positions -> Painter draws to viewport -> Event system handles clicks/scroll/keys
Layered Architecture Stack
Each layer maps to “files/modules” you can implement
architecture_stack.html
UI Layer
Top: What user touches
ui/main_window.(c|cpp) Window + widgets
  • Creates window, toolbar, tabs, viewport surface (SDL2/Win32/Qt etc.)
  • Wires buttons: back/forward/reload, address bar, tab switching
  • Displays status: loading spinner, errors, URL, progress
ui/input_events.(c|cpp) Mouse/Keyboard
  • Converts OS input into browser events (click, scroll, keypress)
  • Dispatches events to viewport (links, text selection, scrolling)
Browser Controller Layer
Glue: UI ↔ Engine
browser/navigation.(c|cpp) Navigate + history
  • Accepts NavigationRequest (URL, method, headers)
  • Owns History stack, Back/Forward behavior
  • Starts loads, cancels loads, handles redirects
browser/tab_manager.(c|cpp) Tabs
  • Creates/tears down per-tab state (document, scroll, history)
  • Routes UI events to active tab
Networking Layer
HTTP + TLS
net/http_client.(c|cpp) Requests
  • Builds HTTP requests, parses status line + headers
  • Supports redirects, chunked encoding (optional), gzip (optional)
  • Returns response bytes + metadata
net/tls.(c|cpp) mbedTLS/OpenSSL
  • Handles HTTPS: certificate validation, handshake, encrypted streams
  • Exposes a simple “secure socket” API to http_client
net/cache.(c|cpp) Cache (later)
  • Caches responses, respects basic cache headers
  • Speeds up repeat loads
Parsing Layer
HTML → DOM
parse/html_tokenizer.(c|cpp) Tokens
  • Splits input into tags, attributes, and text
  • Start with a minimal subset (a, p, div, img)
dom/dom_tree.(c|cpp) DOM nodes
  • Represents elements, text nodes, attributes
  • Allows traversal: parent/children/siblings
parse/css_parser.(c|cpp) CSS (later)
  • Parse tiny CSS subset (font size, color, margin)
  • Compute “computed style” per node
Layout Layer
DOM → Boxes
layout/layout_engine.(c|cpp) Flow layout
  • Builds a layout tree (block boxes + inline text runs)
  • Computes positions, line breaks, scroll height
  • Start with: vertical flow + text wrapping
layout/font_metrics.(c|cpp) Measure text
  • Measures text width/height for wrapping
  • Uses platform font APIs or a simple library
Rendering/Paint Layer
Boxes → Pixels
gfx/painter.(c|cpp) Draw
  • Draws background rectangles, text, basic borders
  • Supports clipping + scrolling viewport
gfx/image_decode.(c|cpp) Images (later)
  • Decode PNG/JPEG (stb_image or similar)
  • Rasterize into the viewport
JavaScript + Web APIs
Big jump
js/runtime_embed.(c|cpp) QuickJS/JSC
  • Embed a JS engine (do not write your own)
  • Expose DOM bindings, timers, events (minimum subset)
  • This step multiplies complexity (security + correctness)
ONE SIMPLE LOAD PATH (modules) ui/main_window -> browser/navigation -> net/http_client (+ net/tls) -> parse/html_tokenizer -> dom/dom_tree -> layout/layout_engine -> gfx/painter (draw to viewport)
